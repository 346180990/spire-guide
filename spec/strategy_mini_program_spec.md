# 股票策略参考小程序：产品 Spec & Design

> 版本：MVP v1.0  
> 定位：策略信号查看、历史信号回看、回测验证与版本对比。  
> 重要边界：本产品第一版提供研究参考，不自动下单；任何信号都必须显示数据时间、计算时间、信号有效日期和数据质量状态。

## 1. 产品目标

### 核心目标
1. 打开小程序后，快速知道每个策略**最新一次计算结果是什么**，今天/下一交易日有哪些买入、卖出、观望信号。
2. 可指定历史交易日，查看“当时基于已知数据会产生什么信号”，避免用今天的数据解释过去。
3. 可配置标的、策略参数、运行频率和交易成本，执行回测。
4. 每次运行保存完整快照；能与之前的回测对比，帮助判断代码修改是否真的改善策略。
5. 数据过期、运行失败、缺失行情或策略版本变化时，用户能明显看出来，不把旧信号误认为最新信号。

### 非目标（第一版不做）
- 不自动买卖，不直接连接券商下单。
- 不承诺收益，不把“策略信号”写成确定性买入建议。
- 不在没有数据支持时伪装成实时行情。
- 不允许历史日期查询使用该日期之后的数据。

## 2. 设计原则

- **先给结论，再给证据**：买入/卖出/观望状态优先展示；下面说明触发原因、指标数值和数据时间。
- **时间必须可见**：任何信号都显示“数据截至”“计算完成”“信号适用日期”。
- **历史回看与回测分开**：回看回答“当时会看到什么信号”；回测回答“按规则执行后，整个区间表现如何”。
- **参数可追溯**：每个信号和回测都绑定策略代码版本、参数版本、标的范围、数据源和执行假设。
- **渐进式参数**：常用参数在基础区，容易误调或复杂参数放在高级设置；显示默认值与当前值。
- **推荐不等于买入**：推荐关注列表是“适合研究/数据齐全/流动性较好”的候选集合，不是收益承诺。

## 3. 信息架构

底部导航建议 4 项：
1. **策略**：策略列表、最新信号、状态和最近一次运行时间。
2. **回测**：新建回测、运行历史、结果详情、版本对比。
3. **关注**：多标的管理、策略可用标的推荐、分组。
4. **我的**：数据源状态、定时运行、提醒设置、系统说明。

核心流程：
- 策略列表 → RSRS 策略详情 → 今日/历史信号 → 买入/卖出/观望标的详情。
- 策略详情 → 参数设置 → 保存参数版本 → 运行回测 → 回测结果 → 与历史运行对比。
- 回测运行历史 → 选择两次运行 → 指标差异、代码/参数/数据差异。

## 4. 页面设计规格

### 4.1 策略列表页（首页）

**页面顶部**
- 标题：策略
- 总体行情/数据状态：`数据正常 / 数据延迟 / 数据异常`
- 显示：`行情截至 2026-10-23 15:00`、`最近刷新 15:18`（示例值；实际由数据源返回）
- 快捷入口：历史日期、运行记录。

**策略卡片字段**
- 策略名称、类型标签、启用状态。
- 最近信号：`买入 / 卖出 / 观望 / 暂无结果`。
- 信号适用日期。
- 信号摘要：买入 N 个、卖出 N 个、观望 N 个。
- 最近运行时间、行情数据截至时间。
- 最近一次运行：成功、失败、执行中、数据过期。
- 快捷操作：查看信号、运行回测、参数设置。

**示例卡片（仅为 UI 假数据）**
- RSRS 择时：`观望`；信号日期 `2026-10-23 盘后`；适用 `下一交易日`；数据 `已更新`。
- ETF 轮动：`待运行`；标的 `8`；上次运行 `昨日 15:20`。

**交互**
- 点卡片进入策略详情。
- 过滤：全部、运行中、异常、已停用。
- 搜索策略名。
- 下拉刷新只能触发查询/刷新，不能假定行情源已经更新；刷新后必须显示实际数据时间。

### 4.2 策略详情 / 最新信号页

顶部信息：
- 策略名、策略版本、运行状态。
- 日期切换：`最新信号`、`选择日期`。
- 明确展示三种时间：
  - **数据截至**：本次计算实际使用的最后一条行情时间。
  - **计算完成**：后端本次计算结束时间。
  - **信号适用**：信号可用于哪个交易日/时段。

**结论区**
- 大状态：`买入 / 卖出 / 观望 / 数据不足 / 运行失败`。
- 一句话解释：例如“当前信号未达到买入或卖出条件”。实际文字必须由策略规则和指标计算结果生成，不能写死。
- 标记：`模拟信号，不会自动下单`。

**信号摘要**
- 买入数量、卖出数量、观望/持有数量。
- 买入列表：代码、名称、信号强度/触发值、参考价格、触发原因。
- 卖出列表：代码、名称、触发原因、当前策略状态。
- 观望/持有列表：代码、当前状态、未触发条件（如策略能提供）。
- 每只标的详情需显示：信号依据、指标值、数据时间、下次有效交易日、代码/参数版本。

**操作按钮**
- `查看历史信号`
- `运行回测`
- `调整参数`
- `查看本次运行日志`

**时间逻辑（强制要求）**
- 如果 RSRS 使用某交易日完整的最高价、最低价或收盘价，盘后才能计算完成；这个信号默认只能用于下一交易日，不得显示为“当日开盘可买”。
- 若实现盘中信号，必须明确盘中数据频率、计算时间和可用数据范围；不能把日线策略简单设置成每分钟运行。

### 4.3 历史信号回看页

目的：查看某个历史时点“当时可知道的信号”，不是对历史行情重新做事后解释。

**控件**
- 交易日选择器：只能选交易日；非交易日自动提示最近交易日，不静默替换。
- 查看口径：
  1. `盘后信号`：使用所选日已完成的日线数据，结果适用于下一交易日。
  2. `盘中快照`：仅当有对应历史盘中数据时开放；否则置灰并说明原因。
- 结果显示：信号状态、候选标的、当时指标值、数据截至、信号适用时间。
- 提示：`历史信号仅使用所选时点可获得的数据`。

**防未来数据规则**
- 历史日期 D 的查询不得读取 D 之后的行情、财报修订值或未来成分股信息。
- 日线信号使用 D 日完整 OHLC 时，信号最早从 D 之后的下一交易日执行。
- 历史回看和回测必须调用同一份信号计算逻辑，避免两套代码结果不一致。

### 4.4 参数设置页

**基础参数**
- 计算标的模式：`按基准指数择时` / `每个标的独立计算`。只有策略代码支持的模式才可选；默认遵循源 Notebook 的实际逻辑，不可擅自改变。
- 关注/交易标的：多选，支持搜索、分组、全选、取消选择。
- 计算周期：日线、周线、月线（只展示策略实际支持的选项）。
- 运行频率：
  - 每个交易日盘后（RSRS 日线默认推荐）
  - 每周指定交易日
  - 每月指定交易日
  - 盘中指定频率（仅在数据源和策略均支持时开放）
- 执行时间：按 Asia/Shanghai 时区配置，默认在数据源确认当日行情完成后运行。
- 买卖阈值、回归窗口、标准化窗口等 RSRS 参数：字段名称、单位、范围、默认值必须从所采用的策略实现中读取，不要凭空填入未验证的默认值。

**高级参数（折叠区）**
- 初始资金。
- 单标的最大仓位 / 最大持仓数。
- 手续费、印花税（按市场与品种配置）、滑点。
- 信号执行假设：下一交易日开盘 / 下一交易日指定时点 / 其他可验证的规则。
- 是否允许重复买入、是否允许空仓、再平衡规则（仅当策略支持）。

**保存行为**
- 保存时创建新的参数版本，不能覆盖已经用于历史回测的旧版本。
- 显示“本次修改与上一版本差异”。
- 修改参数后提示：当前最新信号仍对应旧版本，需重新运行才会生成新信号。
- 参数合法性校验；不合法时在字段附近说明原因，不允许静默截断。

### 4.5 关注标的管理页

**功能**
- 支持多个标的同时关注，支持分组，例如：宽基 ETF、行业 ETF、个股观察。
- 搜索代码/名称，添加/删除，批量勾选。
- 展示代码、名称、市场、品种、流动性/数据覆盖状态、所属策略。
- 支持导入/导出关注清单（可放到 P1）。

**推荐关注区**
- 分区展示“策略适配候选”“数据完整候选”“高流动性候选”。
- 推荐依据要透明：例如历史数据完整、成交额达到用户设置门槛、属于策略允许的品种。
- 默认示例可提供宽基指数/ETF作为研究起点；具体候选应由数据源、市场范围和策略支持的标的类型动态生成。
- 不显示“推荐买入”或暗示未来收益；推荐关注只表示可纳入研究范围。

### 4.6 回测配置页

**必填项**
- 策略及参数版本。
- 回测起止日期。
- 标的范围/关注列表。
- 初始资金。
- 手续费与滑点。
- 信号计算频率与成交假设。

**高级可选项**
- 基准指数。
- 仓位与持仓约束。
- 是否使用停牌、涨跌停、复权、分红等处理规则（由回测引擎能力决定，需显示实际采用的规则）。
- 样本外区间或训练/验证划分。

**运行前预检**
- 日期范围是否有足够数据。
- 标的行情缺失率。
- 参数是否合法。
- 是否存在信号日与成交日错位。
- 是否可能使用未来数据。
- 预计计算任务状态（不需要承诺耗时）。

### 4.7 回测结果页

**顶部摘要**
- 回测运行 ID。
- 策略代码版本/提交号或内容哈希。
- 参数版本。
- 数据源与数据区间。
- 运行时间、运行状态。

**核心指标**
- 累计收益、年化收益、最大回撤、夏普比率、波动率、胜率、交易次数、换手率、成本占比。
- 对照基准的收益与回撤。
- 资金曲线、回撤曲线、月度收益图。
- 交易明细：时间、标的、买卖方向、成交假设价格、数量/权重、费用、触发信号。

**结果质量检查**
- 缺失行情、重复数据、异常价格、空信号/异常交易数量。
- 交易成本是否开启。
- 是否存在未来数据风险检查结果。
- 若关键检查失败，结果仍可查看，但必须有醒目的“不可用于策略判断/需要复核”状态。

### 4.8 历史运行与版本对比页

每次运行不可变，至少保存：
- 运行 ID、策略代码版本、参数快照、标的集合、数据源版本/更新时间、回测区间、成交假设、运行日志、指标结果。

**对比能力**
- 选择两次或多次运行。
- 指标表对比：收益、最大回撤、夏普、波动率、胜率、换手率、费用、交易次数。
- 差值列：本次 - 基准版本。
- 资金曲线叠加、回撤曲线叠加。
- 参数差异、代码版本差异、数据范围差异。
- 展示“本次改变了什么”，避免把数据区间变化误当成代码优化效果。
- 同样参数、同样代码、同样数据重复运行时，指标应一致或解释随机性/数据更新造成的差异。

### 4.9 运行记录 / 提醒

- 运行状态：排队、执行中、成功、失败、数据不足、已取消。
- 展示开始/结束时间、日志摘要、失败原因、重试入口。
- 可配置运行成功/失败、产生买卖信号、数据延迟的提醒。
- 首版可先做小程序内通知/消息页；外部订阅消息按平台权限后续接入。

## 5. 设计视觉规范

- 风格：轻量、清晰、偏工具型金融产品；白底、深灰文字、蓝色主操作。
- 正向/负向颜色可使用红涨绿跌或红买绿卖，但必须全局统一，并允许用户切换；不要只靠颜色传递状态，需同时有文字与图标。
- 关键状态用短标签：最新、延迟、异常、待运行、成功、失败。
- 重要数字采用等宽数字风格；指标单位和统计区间紧跟数字显示。
- 页面首屏优先级：信号结论 > 数据时间 > 买卖清单 > 依据/风险 > 历史与回测入口。
- 采用卡片分组和折叠的高级设置，避免一次暴露过多量化术语。
- 空状态必须提供操作建议，如“暂无信号：先检查数据时间/运行记录”，而不是空白页。

## 6. 数据新鲜度与时效性要求

**每个数据接口都要返回数据时间，不能用前端当前时间代替行情时间。**

- 日线模式：展示最近完成的交易日和最后一条行情的时间；仅当数据源确认日线完整后运行正式盘后信号。
- 盘中模式：展示行情源时间、后端接收时间、策略计算时间；数据源不支持历史分钟数据时，不允许做历史盘中回看。
- 数据过期时：显示“信号已过期”，保留上次结果供查阅，但不标成最新；阻止将过期结果误认为当日有效信号。
- 运行失败/数据缺失时：信号状态显示“不可用”，不能默认回退为“观望”。
- 交易日历使用交易所日历；非交易日不运行正式交易信号，允许查看最近一次有效结果。
- 所有时间统一使用 Asia/Shanghai，并明确时间类型：行情时间、计算时间、信号适用时间。

## 7. 推荐后端数据结构

- `Strategy`: 策略元信息、策略类型、默认参数版本、当前启用状态。
- `StrategyCodeVersion`: 代码版本/哈希、来源、创建时间、说明。
- `StrategyConfigVersion`: 参数快照、关注标的、运行频率、创建时间。
- `SignalSnapshot`: 策略/代码版本/参数版本、信号日期、数据截至时间、计算时间、适用日期、结论、标的明细。
- `BacktestRun`: 运行 ID、配置快照、数据版本、区间、执行假设、状态、日志、指标。
- `BacktestTrade`: 每笔模拟交易的信号、成交时间、成交价格假设、费用、数量/权重。
- `MarketDataStatus`: 数据源、标的、最后更新时间、缺失状态、完整性检查结果。
- `ScheduledJob`: 策略、频率、时区、下次运行时间、运行结果。

## 8. 关键验收标准（必须）

1. 用户能在首页看到最新信号、行情截至时间、计算完成时间和信号适用日期。
2. 用户能选择过去任意有效交易日，并查看仅使用当时可得数据生成的信号。
3. 日线策略不会把盘后才知道的信号显示成当日开盘可执行信号。
4. 用户可以关注多个标的，并看到哪些候选因数据不完整或策略不支持而不能计算。
5. 用户可以修改策略支持的参数并生成新版本；旧版历史信号与回测结果保持不变。
6. 用户可以启动回测，看到运行状态、核心指标、资金曲线、交易明细和质量检查。
7. 用户至少能比较两次回测的指标、曲线、参数、代码版本和数据范围。
8. 数据延迟、数据不足、策略运行失败必须与“观望”严格区分。
9. 相同代码、参数、数据区间和执行假设应得到可复现的结果；若不能复现，必须记录原因。
10. 第一版无真实下单入口；信号和回测页面均明确标示为研究参考/模拟结果。

## 9. 实施优先级

### P0：首版必须有
- 策略列表与策略详情。
- 最新信号与清晰的数据/计算/适用时间。
- 历史日期信号回看（盘后口径）。
- 多标的关注管理。
- RSRS 基础参数配置与参数版本留存。
- 回测任务、核心指标、交易明细、运行日志。
- 历史回测列表与两次运行对比。
- 数据过期/缺失/计算失败状态。

### P1：第二阶段
- 周频/月频调度、运行失败/信号提醒。
- 更多策略模板、标的分组和清单导入导出。
- 样本外评估、分市场阶段分析、参数敏感性分析。
- 更完整的未来数据风险与异常交易自动检查。

### P2：后续再评估
- 盘中策略与历史分钟级信号回放。
- 券商账户持仓同步、实盘监控。
- 自动下单（必须独立设计交易授权、风控、确认与审计，不纳入首版）。

## 10. 给开发实现的特别说明

- RSRS 的实际公式、窗口期、标准化方法、买卖阈值、交易规则必须从指定 Notebook/所选代码版本中提取；页面不要擅自假设一套“标准 RSRS”替代原实现。
- 将策略信号计算做成可复用的纯计算模块，历史回看与回测调用同一套计算逻辑；行情读取、执行模拟、页面展示分层。
- 信号结果必须保存为快照，不能在用户打开旧日期时悄悄用最新代码和最新参数重算并覆盖历史结果。
- 后续代码优化需能用旧版参数/同一数据区间复跑，以便做可比实验。
- 标的推荐逻辑优先考虑：策略支持范围、数据完整性、流动性门槛和用户选定市场；不依据未经验证的未来收益排名推荐股票。
