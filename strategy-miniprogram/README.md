## RSRS 实现（三个指标 + 可选均线过滤）

| 名称 | 公式 | 说明 |
|---|---|---|
| `标准分RSRS` | `(β - roll_mean_M) / roll_std_M` | 回归斜率 β 的 M 日标准分 |
| `修正标准分RSRS` | `标准分 × R²` | 拟合越好信号越强，震荡市自动减弱 |
| `右偏修正标准分RSRS` | `修正标准分 × β` | 收益最高、回撤也最大，建议配过滤 |

- 回归：`high = a + b·low`，β 是斜率，`R² = corr(high, low)²`
- 阈值状态机：`> 开仓阈值` 开仓；`> 平仓阈值` 持有；`<= 平仓阈值` 平仓
- 回归窗口对齐：默认 `align='notebook'`（窗口 `[i-N, i)` 不含当日），与 notebook 逐位一致
- **MA 趋势过滤**（`trend` 开关，默认关）：信号为持仓 **且** MA20 上倾（T−1 > T−3）才真的持仓，
  历史不足时一律空仓。这是研究脚本里的「钝化」（`scripts/rsrs-yearly.mjs`），
  **不是** notebook 的 `R^(2q)` 钝化——两个「钝化」不是一回事
- notebook 原本六个版本，2026-10-25 精简掉三个（原始斜率 / R^(2q) 钝化 / 成交额加权钝化），
  连同只服务于钝化的 `q`（收益波动分位）与 WLS 一起存档到 `reference/rsrs/rsrs-6kinds.archive.js`

### 为什么留这三个

同一套参数下跑 5 个指数 × N∈{16,18,19} × M∈{300,700} × S∈{0.4,0.7,1.0} × 2 个区间，共 1080 个回测单元（不含均线过滤）：

| 指标 | 平均超额年化 | 排名均值 | 进前二 |
|---|---|---|---|
| **标准分RSRS** | **+1.71%** | 3.33 | 64/180 |
| **修正标准分RSRS** | **+1.60%** | 3.37 | 52/180 |
| 钝化RSRS | +1.36% | 3.47 | 56/180 |
| 成交额加权钝化RSRS | +1.30% | 3.65 | 55/180 |
| 右偏修正标准分RSRS | +1.29% | 3.40 | 61/180 |
| RSRS（原始斜率） | −0.12% | 3.78 | 72/180 |

原始斜率的「72 次进前二」是假象：β≈1 永远大于 0.7 阈值，等于长期满仓，熊市里反而显得抗跌。

**右偏单独排第 5，但要它是因为「右偏 + MA20 过滤」是风险调整后最好的一套**（沪深300，2006-2026：
年化 12.8%、回撤 −25.0%，而裸右偏是 12.7% / −56.5%）。过滤器是开关，不是默认：
上证50、中证红利加上反而更差，创业板则明显受益。

### 基准值（回归基线）

用本仓库沪深300 日线（东财，5294 根）跑 2008-03-25 ~ 2019-12-31、不计成本：

| 指标 | 年化 | 累计 | 最大回撤 | 持仓天数 | 交易次数 |
|---|---|---|---|---|---|
| 标准分RSRS (18,700,0.7) | **12.42%** | 295.85% | 40.56% | 1342 | 49 |
| 修正标准分RSRS (18,600,0.7) | 13.14% | 326.60% | 40.52% | 1385 | 43 |
| 右偏修正标准分RSRS (18,700,0.7) | 10.77% | 232.68% | 42.97% | 1643 | 36 |

`scripts/check-strategy.mjs` 把这三行钉住（年化差 < 0.5pt、交易次数必须完全一致），公式被动过会立刻失败。

> notebook 原文的 10.26%（钝化）/ 11.83%（右偏 18/600）对应已删除的 R^(2q) 钝化与另一组参数，留档在归档文件里。

## 数据策略：本地优先，线上兜底

每个标的分开判断，优先顺序固定：

| 级别 | 来源 | 条件 | 有效期 |
|---|---|---|---|
| ① | **本地缓存** | 根数够（≥ 需要的 95%）且未过期 | 信号 12 小时 / 回测 **7 天** |
| ② | **内置样例** `core/seed.js` | 无缓存、缓存太短或已过期 | 构建时快照 |
| ③ | **线上抓取** | 上面都不满足，或用户下拉刷新 | 每次实时 |

要点：

- **回测对「最新一根」不敏感**，所以 TTL 放宽到 7 天：同一份本地数据可以反复跑参数扫描，不再每次联网
- **云函数没部署 / 没网 / 断网时也能用**：自动退到内置样例，页面明确显示「内置样例」并提示非实时
- 内置样例覆盖沪深300 与中证500 各 3600 根（2011-12 起），由 `node scripts/make-seed.mjs` 生成，**要更新数据就重跑它**
- 无论走哪一级，UI 显示的「数据截至」始终是数据自带的最后交易日，绝不用本机时间顶替
- 缓存过期不等于不可用：先当占位符，联网成功后再替换；全失败则返回旧数据并标 `stale`

### 测试覆盖（第 11 组断言）

- 离线冷启动 → 用内置样例也算出信号，且 asOf 来自数据
- 首次回测会联网（缓存不够长）→ 第二次回测**不再联网**
- 两次回测指标完全一致（可复现）
- `localOnly` 模式完全不触发云函数

## 数据与时间语义

- 云函数只返回数据源自带的最后交易日，`asOf` 由数据决定，**不用本机时间代替**
- 每个信号同时展示：**数据截至** / **计算完成** / **信号适用**
- 日线信号在收盘后才可计算 → 默认适用下一交易日（次日收盘成交，可改次日开盘）
- 历史回看只截取 `date <= 所选日期` 的行情参与计算，物理上排除未来数据
- 数据过期、长度不足、计算失败分别对应 `stale / insufficient / failed`，**绝不退化为「观望」**

## 自检

```bash
node scripts/check-strategy.mjs
```

128 条断言（其中 2 条要联网，断网时会失败），覆盖：

1. 公式恒等性（修正 = 标准分 × R²、R² ∈ [0,1]、预热长度、已删指标抛错、三个指标都在）
2. 修正标准分的口径（|修正| ≤ |标准分|、z 量级）
2b. **MA 趋势过滤**（只减不加、T−1 > T−3 才持仓、开头空仓、截断无未来函数、开过滤后回撤变小）
3. 阈值状态机的开平仓序列
4. **结果锁定**（本仓库数据上的年化/回撤/交易数基线，公式被动过就失败）
5. 无未来数据（截断不变性）
6. 可复现性（两次运行完全一致）
7. 参数与边界报错
8. 快照三时间、`insufficient → unavailable`、参数校验、预设来源正确
9. 小程序静态检查（页面四件套、tabBar、JSON、组件引用、WXML 不误用 HTML 标签、require 路径）
10. wx mock 端到端：缓存命中 → 信号 → 回测 → 落盘 → 参数版本不可变 → 关注列表驱动范围

## 已知限制

- 只有 RSRS 一个可用策略；ETF 轮动 / 双底可转债 在首页显示「规划中」且不可点
- 不做盘中信号、不做定时调度（需后端调度器）、不做订阅消息
- 回测在小程序本地跑，日线上限 3600 根（约 14 年）；M 越大可用区间越短，预检会提示
- 行情来自东财/腾讯，可能与交易所官方数据存在细微差异；notebook 用的是聚宽数据，故按容差而非逐位校验
- 不自动下单，所有页面均标示为模拟结果
