# 策略助手 · Web 版

把原来的小程序改成一个网页应用：**服务端算策略，浏览器只负责展示**。

这样做的三个理由：

1. **只有一份策略代码** —— 直接复用 `strategy-miniprogram/core/`（RSRS 三指标 + 均线过滤、回测、信号），不重写、不会两边算出不同结果
2. **浏览器抓不到行情** —— 东财/腾讯都没有 CORS，必须服务端代理，顺手就有了磁盘缓存
3. **微信推送天然属于服务端** —— 定时任务和推送脚本要和策略跑在一起

## 界面

桌面 Web 布局：顶部导航（策略 / 防守 / 回测 / 数据 / 源码）+ 左右分栏。

**策略页**：左侧是日期条、结论区（结论 + 数据截至 + 买入/卖出/持有/观望计数 + 理由）、标的明细表；
右侧侧栏是策略参数（含 **MA20 趋势过滤**开关）、微信推送、**每日计算**（今天两次跑没跑 + 最近流水）。

**回测页**：**左侧宽阔区域是结果**（9 项指标 + 360px 净值曲线 + 交易明细），右侧窄栏是回测表单（340px）。图表占满宽栏，**鼠标移上去有十字准星和气泡**：显示该日期、策略净值、买入持有净值，以及各自相对起点的涨跌幅（手机上是手指拖动）。打开页面会自动展示最近一次回测结果，不用先跑一次。

**防守页**：时变夏普 120 + MA200 双条件开关。左侧是结论（持有/空仓 + 上次翻仓）、标的状态表（收盘 / MA200 / 距 MA200 / T 夏普 / 状态 / 上次翻仓）、同规则回测；右侧是参数与回测区间。规则与实测见根目录 README「防守开关」。

**数据页**：左侧是当前支持选择的 11 个标的，点一个就能看到策略实际拿到的数据——
最近 20 根 K 线（开高低收量涨跌），外加一排自动体检
（日期升序 / 重复 / 非法价 / 单日 >20% / 最大空档 / 距今天数）。

**源码页**：只列**策略核心**（指标 / 信号 / 回测 / 绩效 / 标的 / 校验 / 格式化），右侧带行号展示代码，只读。

窄屏（≤1080px）自动收成单列，标的明细在手机上从表格变成两行堆叠，所以同一个页面手机也能用。

截图见 `reports/web-desktop-strategy.png`、`reports/web-desktop-backtest.png`。

## 启动 / 停止（Windows 常驻）

三种方式，任选：

| 方式 | 命令 | 特点 |
|---|---|---|
| **计划任务（推荐）** | 双击 `web\install-task.ps1` | 注册为登录自启，进程挂在任务计划程序下，**关掉终端/会话也不停** |
| 后台脚本 | 双击 `web\start.ps1` | 脱离终端常驻，但重启电脑后不会自启 |
| 前台 | `node web\server.mjs` | 占用一个终端窗口，Ctrl+C 停止 |

停止：

```powershell
powershell -File web\stop.ps1          # 按端口 8090 结束进程
powershell -File web\install-task.ps1 -Remove   # 顺便卸载计划任务
```

日志在 `web\data\server.out.log` / `server.err.log`。

> 注意：用 DSH 会话里的后台任务启动的进程，会话中断时会被一起收掉；计划任务不受影响。

## 结论必须能解释「为什么」

不满足于「3 个标的仍在持有区间」这种空话。每条结论都带**可核对的依据**：

| 结论 | 生成的理由（真实输出） |
|---|---|
| 持有 | 指标 **-0.3147** 高于平仓线 **-0.7**（高出 **0.3853**），未触发平仓 → 继续持有（**已连续持有 146 个交易日**） |
| 观望 | 指标 **0.1429** 低于开仓线 **0.7**（还差 **0.5571**），未触发开仓 → 维持空仓 |
| 买入 | 指标 **1.1242** 高于开仓线 **0.7**（高出 **0.4242**），上一交易日为空仓 → 开仓买入 |
| 卖出 | 指标 **-0.9146** 低于平仓线 **-0.7**（低 **0.2146**），上一交易日持仓 → 平仓卖出 |

汇总层也会点名：

> 维持持有。**2 个维持持有**（指标未跌破平仓线 -0.7）：上证50 -0.3147、中证红利 0.3423；**3 个观望**（指标未达开仓线 0.7）：沪深300 0.1429、中证500 0.2305、创业板指 0.1657

页面上每个标的还额外显示：`R²`（拟合优度）、`已连续持有 N 个交易日`、`阈值 0.7 / -0.7`。

理由不是模板硬编码，而是**由当日数值和阈值算出来的**，所以改成别的参数（比如开仓线 1.0）理由也会跟着变。

## 关注标的会同步到服务端

界面上勾选的标的会 `POST /api/watchlist` 存进 `data/state.json`，**定时推送用的就是这一批**，不会出现「界面看 5 个、推送只推 3 个」。

也可以直接改 `config.json` 的 `symbols` 作为初始值。

## 回测才是「选中策略去回测」

回测表单里现在有**策略选择**，不再偷偷用策略页的参数：

| 字段 | 说明 |
|---|---|
| **策略** | 3 个指标版本任选（标准分 / 修正标准分 / 右偏），下面一行显示该版本的原理说明 |
| **回归窗口 N / 标准化窗口 M** | 与策略页独立，想试 M=300 vs M=700 直接改 |
| **开仓阈值 / 平仓阈值** | 同上 |
| **MA20 趋势过滤** | 勾上就是研究脚本里的「钝化」：信号为持仓且均线上倾才真的持仓。默认关 |
| 标的 / 起止 / 资金 / 成交假设 / 费率 / 滑点 | 常规回测参数 |

两个快捷按钮：

- **用策略页参数** —— 把策略页当前的指标版本与参数抄过来
- **套用标的预设** —— 用 notebook 里针对该指数的推荐参数（如沪深300 = 18/700/0.7）

结果标题会写清用的是哪套策略：

> 「沪深300」标准分RSRS N=18 M=300 开0.7/平-0.7 · 2020-01-02 → 2026-10-23

### 三个指标 + 过滤，结果确实不一样（沪深300，2020-01-02 → 2026-10-23，含费滑，N=18 M=700）

| 策略 | 年化 | 回撤 | 夏普 | 交易 | 超额（对买入持有） |
|---|---|---|---|---|---|
| 标准分RSRS | -0.55% | 38.90% | -0.20 | 24 笔 | -0.38% |
| 修正标准分RSRS | -0.39% | 40.87% | -0.19 | 19 笔 | -0.22% |
| 右偏修正标准分RSRS | -1.20% | 43.42% | -0.23 | 17 笔 | -1.03% |
| 右偏 + MA20 过滤 | **+2.21%** | **16.85%** | -0.02 | 35 笔 | **+2.38%** |

这段区间买入持有本身年化 -0.17%。裸指标都没跑赢，**加上 MA20 过滤后回撤从 43% 压到 17%、收益转正**——
这就是研究脚本里「钝化·右偏」那套东西，现在只是变成了一个开关。

注意代价：过滤把换手从 17 笔推高到 35 笔（多次进出），成本和假信号都变多；
它擅长「躲跌」，不擅长「多赚」，2017 年后全样本的超额基本靠回撤换来的。

## 源码页：只看策略核心

顶部「源码」页签（直达 <http://127.0.0.1:8090/#source>）把服务端实际加载的**策略代码**只读地摆出来：

- 只列 `strategy-miniprogram/core/` 里的 7 个文件（指标 / 信号 / 回测 / 绩效 / 标的 / 校验 / 格式化），带行数
- 右侧带行号的代码，注释、字符串、数字、关键字有基础着色
- **原始文件** —— 新标签页打开纯文本（`/api/source?id=rsrs&raw=1`），方便另存后 diff
- **复制全文** —— 一键复制当前文件（局域网 http 下退回 `execCommand`，不依赖安全上下文）

要点是**读磁盘上的真实文件**，不是往 `public/` 拷一份副本，所以网页上看到的就是回测/信号正在跑的那份，不会出现「文档里的公式和代码里的公式对不上」。

安全边界：`/api/source` 只认 `lib/source.mjs` 里登记过的白名单 id，URL 里的路径永远不拼进 `fs`（`?id=../config.json` 直接 404）；远端访问照旧走整站令牌。

## 按日期验证（默认今天）

策略页顶部有一个**查看日期**，默认今天：

- 选今天 → 用最新可得行情算，等价于「现在的信号」
- 选历史某天 → **只用该日收盘及之前的数据**重算，用来验证当时会得出什么买卖

实现方式是直接把日期传给 `signal.buildSnapshot({asOfDate})`，核心库会**物理截断** bars
（`slice(0, idx+1)`），不是算完再筛，所以不可能读到未来数据。

页面会显示黄色提示条：

> 验证模式：用 2015-06-12 收盘及之前的数据计算（3600 根），信号在 2015-06-15 生效；不含该日之后的任何数据。

其中「2015-06-15」是数据里真实存在的下一个交易日（自动跳过周末与节假日缺口）。

日期会写进 URL，可以分享/收藏：

```
http://127.0.0.1:8090/?date=2015-06-12#strategy
```

**自检里有一条硬证明**：用 `asOfDate` 截断 与 把 bars 物理截断，两者算出的结论/指标值必须完全相等。

## 每天什么时候跑

默认两个时间点（北京时间，工作日）：

| 时间 | 名称 | 干什么 | 行情 | 推送 |
|---|---|---|---|---|
| **08:45** | 盘前 | 用**昨日收盘**的最终数据重跑，作为今天的操作依据 | 只强制刷关注标的 | 结论变化才推 |
| **18:00** | 盘后 | **先把 11 个标的的行情全部拉到最新**，再算一遍，得到**明日**的信号并留档 | 全量刷新（`refreshBars`） | 结论变化才推 |

**为什么盘后要专门拉一次行情**：信号计算只覆盖「关注标的」，而数据页/回测要看全部 11 个。
18:00 先跑 `refreshAllBars()`（3 个并发、每个拉 3600 根、写磁盘缓存），信号计算随后直接读刚刷新的缓存，
**一次抓取、两边受益**；抓不动的标的会逐个记下来（数据源限流/延迟/断网都是常态），不会整体失败。

**为什么要盘前再跑一次**：盘后 18:00 抓数据时，数据源不一定已经更新完整（东财/腾讯收盘后延迟几分钟到几十分钟不等）。
盘前这次 `force=true` 强制刷新，能把更正的收盘价吃进来。所以盘前这次是**真正下手前的那次计算**。

**为什么不重复推送**：两次都算，但只有「结论签名」（结论 + 各标的 action）变化时才推送。
正常情况一天最多一条；只有数据被修正导致结论变了，才会补发一条。

改时间 / 改刷新策略：

```json
"scheduler": {
  "enabled": true,
  "slots": [
    { "at": "08:40", "label": "盘前", "force": true,  "onlyOnChange": true, "refreshBars": false },
    { "at": "18:00", "label": "盘后", "force": false, "onlyOnChange": true, "refreshBars": true }
  ]
}
```

或用环境变量：`SA_SCHEDULE="08:40,18:00"`、`SA_SCHED_ENABLED=0`。

页面右侧「每日计算」卡片显示：

- **今天两次跑没跑**：08:45 盘前 / 18:00 盘后，各显示「待运行 / 已算 08:45:12 · 观望 / 今天没跑（当时服务没启动）/ 周末不跑」
- **最近 8 次流水**：北京时间、标签（盘前 / 盘后 / 手动 / 补算）、结论、数据截至、每个标的的买卖动作、**行情刷新 x/y**
- **下一次运行时间**，以及「立即跑一次」按钮（= 手动触发一次盘后任务：先拉全部行情，再算信号）

流水落在 `data/job-log.json`（保留 400 条，约 200 个交易日），`GET /api/jobs/log?limit=20` 可读。
它和 `push-log.json` 的分工：`push-log` 只管推送成败，`job-log` 管「几点算的、用的是哪天的数据、算出了什么」。

**错过的会自动补算**：调度器不是"到点触发一次"，而是每分钟检查"今天已过的时间点里，有没有还没跑过的"。

| 场景 | 行为 |
|---|---|
| 08:45 服务在线 | 准点跑，标签「盘前」 |
| 09:10 才启动服务 | 立刻补跑 08:45，标签「盘前（补算 08:45）」 |
| 19:00 才启动服务 | 只补最晚的 18:00，不会把两个点连着跑两遍 |
| 周末 | 不跑（但跨周末开机也不会补跑周六周日） |

## 数据策略：本地优先，线上兜底

与小程序端同一套逻辑：

```
① 磁盘缓存（够长 + 未过期，默认 7 天）→ ② 内置种子（core/seed.js）→ ③ 线上抓取
```

- **回测对「最新一根」不敏感**，所以缓存 7 天，反复跑参数几乎不联网
- **没有网络 / 抓取失败也能用**：退到内置种子（沪深300、中证500 各 3600 根），页面标「非实时」
- 抓取直接复用小程序的云函数源码（东财为主、腾讯 1600 根上限 + 按日期分页拼长历史）
- 想强制拿最新数据：页面右上角 ⟳，或 `?force=1`

## 微信推送

### 四条路怎么选

| 方案 | 能收到的地方 | 门槛 | 限制 | 适合 |
|---|---|---|---|---|
| **企业微信应用消息** ⭐ | **个人微信**（微信里的「企业微信」通知） | 注册企业微信（个人可注册，免费）+ 建应用 + 开「微信插件」 | 无条数焦虑 | **首选**，日常推送 |
| **企业微信群机器人** | 企业微信群 | 建群 → 加机器人 → 复制 Webhook | 20 条/分钟 | 最快验证，团队一起看 |
| **Server酱** | 个人微信（服务号） | 扫码登录拿 SendKey | 免费 5 条/天 | 最省事，量小 |
| **PushPlus** | 个人微信 | 扫码拿 token | 免费有额度 | 备选 |

> 为什么不选公众号模板消息 / 小程序订阅消息：需要**已认证服务号**（企业主体、年审费用）或用户逐次订阅，个人玩不动。

### 配置（以企业微信群机器人为例，1 分钟）

1. 企业微信里建一个群 → 群设置 → **群机器人** → 添加 → 复制 **Webhook 地址**
2. 复制配置模板：

   ```powershell
   cd D:\project\simplejiaoyi\web
   copy config.example.json config.json
   ```

3. 改 `config.json`：

   ```json
   {
     "push": {
       "enabled": true,
       "provider": "wecom-bot",
       "wecomBot": { "webhook": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的KEY" }
     }
   }
   ```

4. 重启服务，页面「微信推送」卡片点 **发测试**。

### 企业微信应用消息（推到个人微信）

在 `config.json` 里换成：

```json
{
  "push": {
    "enabled": true,
    "provider": "wecom-app",
    "wecomApp": {
      "corpid": "企业ID（我的企业 → 企业信息）",
      "corpsecret": "应用 Secret（应用管理 → 自建应用 → Secret）",
      "agentid": "AgentId（同一个应用页面）",
      "touser": "你的企业微信账号（通讯录里的账号，或 @all）"
    }
  }
}
```

再让账号开通「微信插件」：企业微信 App → 我 → 设置 → 新消息通知 → 微信插件 → 扫码关注。之后应用消息会出现在**微信**里。

### 用环境变量（推荐部署时用）

```powershell
$env:SA_PUSH_ENABLED="1"
$env:SA_PUSH_PROVIDER="wecom-bot"
$env:SA_WECOM_BOT_WEBHOOK="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"
node web\server.mjs
```

完整变量见 `lib/config.mjs` 的 `fromEnv`。

### 没有常驻服务器怎么办

用 GitHub Actions 定时跑一次性脚本（只算信号 + 推送，不提供网页）：

```yaml
on:
  schedule:
    - cron: '45 0 * * 1-5'   # UTC 00:45 = 北京 08:45（盘前）
    - cron: '0 10 * * 1-5'   # UTC 10:00 = 北京 18:00（盘后）
jobs:
  push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: node web/server.mjs & sleep 5 && curl -X POST localhost:8090/api/jobs/run
        env:
          SA_PUSH_ENABLED: '1'
          SA_WECOM_BOT_WEBHOOK: ${{ secrets.SA_WECOM_BOT_WEBHOOK }}
```

## 部署

> 线上部署（买机 → 上传 → systemd → 域名/HTTPS）的完整步骤见 [`deploy/README.md`](../deploy/README.md)，
> 配套脚本：`deploy/deploy.ps1`（Windows 一键推送）、`deploy/bootstrap.sh`（服务器一次性初始化）。

### 本机 / 局域网

```powershell
node web\server.mjs
```

默认只监听 `127.0.0.1`。手机想访问同局域网：

```powershell
$env:SA_HOST="0.0.0.0"
$env:SA_TOKEN="自己设一个长随机串"
node web\server.mjs
```

手机打开 `http://<电脑IP>:8090/?token=你的令牌`。

> **务必设 `SA_TOKEN`**：监听 0.0.0.0 又不设令牌，等于把回测接口开放给整个局域网。

### VPS（systemd）

```ini
# /etc/systemd/system/strategy-web.service
[Unit]
Description=Strategy Assistant Web
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/simplejiaoyi
ExecStart=/usr/bin/node web/server.mjs
Environment=SA_HOST=127.0.0.1
Environment=SA_PORT=8090
Environment=SA_PUSH_ENABLED=1
Environment=SA_WECOM_BOT_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx
Restart=always

[Install]
WantedBy=multi-user.target
```

配 Nginx 反代并套 HTTPS（微信推送是服务端出站，与 HTTPS 无关，但网页访问建议 HTTPS）。

### 数据备份

需要备份的只有 `web/data/`：

- `runs/` 回测记录
- `state.json` 上次结论（删了只会导致下次重复推送一次）
- `bars/` 缓存（删了会自动重抓）

## 安全

| 项 | 说明 |
|---|---|
| `accessToken` | 非本机访问必须带 `?token=` 或 `x-sa-token` 头 |
| `config.json` | **不要提交到版本库**，里面有 webhook key |
| 只读接口 | 所有计算都在内存里做，不执行用户传入的代码 |
| 参数校验 | 复用小程序的 `validate.js`，N∈[5,250]、M∈[20,1500] 等 |
